# 코드 작성 기준

루트 `CLAUDE.md` 에서 `@` 로 자동 로드된다. developer 의 구현 기준이자 code-reviewer 의 유지보수성 점검 기준.

## 정직한 이름

이름이 하는 일을 그대로 말한다. `swap` 이 실제로는 "설치" 라면 `install` 로 고친다 (Decision #11 후속 수정의 실제 사례). 주석도 마찬가지 — "한 키만 바뀐다" 같은 과장된 보장을 적지 않는다. 코드가 실제로 지키는 것만 적는다.

## CQS (명령/조회 분리)

값을 돌려주는 함수는 상태를 바꾸지 않고, 상태를 바꾸는 함수는 값을 돌려주지 않는다. 예외는 "성공 여부" 를 돌려주는 명령 — `arm()` 이 감시 재개 성공을 `Bool` 로 돌려주는 것처럼, 호출자가 후속 동작(통지 여부)을 결정해야 할 때만 허용한다.

## 국소성

관련된 것은 붙여 둔다. 단일 호출처만 있는 헬퍼는 공용 위치로 올리지 않고 호출처 옆에 둔다. 재사용 가능성을 근거로 한 선(先)추상화 금지 — 두 번째 호출자가 생긴 시점에 옮긴다.

## 단일 추상화 레벨

한 함수 안에서 "정책" 과 "메커니즘" 을 섞지 않는다. 예: 저장 정책(어떤 키를 언제 지울지)과 원자적 쓰기 메커니즘(임시 파일 + 심링크 검사 + 권한 설정)은 다른 함수에 있어야 한다.

## 지표 비목적

줄 수·파일 수·커버리지 숫자는 목적이 아니다. 테스트는 "커버리지를 올리려고" 가 아니라 **되돌리면 잡히는 뮤테이션이 있을 때** 추가한다. 파일 분할도 숫자가 아니라 변경 트리거가 갈릴 때 한다.

## 동작 보존

리팩토링은 관측 가능한 동작을 바꾸지 않는다. 동작을 바꾸는 변경과 구조를 바꾸는 변경을 같은 커밋에 넣지 않는다 — 회귀가 생겼을 때 어느 쪽 탓인지 이분하지 못한다.

## 리뷰 가능한 diff

한 커밋은 한 가지를 한다. 무관한 포맷팅·이름 변경을 기능 변경에 섞지 않는다. 커밋 메시지는 한국어 conventional commits 이며, **무엇을 바꿨는지보다 왜 바꿨는지**를 적는다 — diff 가 이미 "무엇" 을 말한다.

## 이 프로젝트 특유의 기준

- **외부 데이터는 관대하게, 사용자 데이터는 보수적으로.** 비공식 엔드포인트 응답은 키 경로가 바뀔 수 있으므로 후보를 여러 개 탐색하고 채울 수 있는 것만 채운다. 반대로 사용자의 `settings.json` 은 읽기에 실패하면 **쓰지 않는다** — 실패를 빈 값으로 강등하면 다음 저장이 파일 전체를 날린다.
- **모르는 것은 보존한다.** 앱이 이해하지 못하는 설정 키·값·타입은 "사용자가 비웠다" 로 해석하지 않고 그대로 둔다.
- **메인 스레드를 막지 않는다.** 셸아웃·네트워크는 타임아웃과 백그라운드 실행이 기본이다.
- **UI 상수는 코드에 흩뿌리지 않는다.** 색은 `Design/Palette.swift`, 시간 표기는 `Services/TimeText.swift` 가 권위다.
